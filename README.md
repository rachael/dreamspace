# Dreamspace

Dreamspace is a calm twilight world of sci-fi and fantasy that you explore in WebXR on a Meta Quest 3. It also runs within
the PICO browser's limits, so the event loaners can open it too. A small floating light called **Lumen** guides you. You
talk to Lumen by voice or text, from inside the headset or hands-free from your iPhone with AirPods. Lumen answers aloud
and **changes the world**: it summons crystals, portals and floating islands, moves them, shifts the mood from twilight to
aurora, and describes what's around you.

- **Brains are swappable:** Claude Code on your subscription (never the API), a local ollama model, or a scripted
  offline brain.
- **Assets are swappable:** curated archetypes, primitive parts generated by the local model, and Meshy later.

The contract every module follows is in `docs/CONTRACT.md`. The why is in `BRIEF.md`. The headset rules are in `CLAUDE.md`.

## Start it (one command)

```
npm run up
```

This one command:
1. Starts ollama if it isn't running, and warms `qwen2.5:3b`.
2. Downloads the whisper speech model the first time (148 MB, checksum verified), then starts `whisper-server`.
3. Starts the app on http://127.0.0.1:8787.
4. Opens a free Cloudflare quick tunnel (no account needed).
5. Checks health, live events and MCP *through* the public URL, so a broken tunnel shows up now and not mid-demo.
6. Prints the links and a QR code for your phone.

| Flag or key | What it does |
|---|---|
| `npm run up -- --local` | No tunnel: this Mac, plus a Quest over USB |
| `npm run up -- --no-whisper` / `--no-ollama` | Skip speech-to-text / skip the local model |
| `npm run up -- --port 8788` | Use another port |
| `u` | Print the links and QR code again |
| `o` | Open the viewer on a USB headset |
| `q` or Ctrl+C | Stop everything |

It stops only what it started. An ollama or whisper that was already running stays up. Logs are in `.data/logs/`.

Other scripts:

| Script | What it runs |
|---|---|
| `npm start` | Just the app, on :8787 |
| `npm run tunnel` | Just the tunnel, pointed at the app |
| `npm run smoke` | The end-to-end smoke test, on its own port and temp data |
| `npm run dev` | The original starter scene, on :5173 |
| `npm run usb` | The original starter, over USB |

**The world key.** The first run writes a random `WORLD_TOKEN` to `.env.local` (gitignored). Every link carries it as
`?t=…`. Pages save it and then strip it from the address bar. Anyone who has a link can talk to your world, so don't
post it anywhere.

**The tunnel URL changes every run.** A quick tunnel gets a new random `*.trycloudflare.com` hostname each time, so
re-scan the QR code and update the claude.ai connector URL after each `npm run up`. A named Cloudflare Tunnel (free
account plus a domain) would give you a stable URL. It isn't set up.

## iPhone (AirPods, hands-free)

1. Run `npm run up` and scan the QR code with the iPhone camera. It opens `…/phone/?t=…` in Safari.
2. Put your AirPods in. Tap the big button once. That tap unlocks the microphone and speech on iOS.
3. Turn on **Hands-free**. It then listens, sends when you pause, speaks Lumen's reply, and listens again. It doesn't
   listen while Lumen is talking, so it never hears itself.
4. Optional: tap Share, then **Add to Home Screen**. The home-screen app has its own storage, so the first time it may
   ask you to paste the phone link. Because the tunnel URL changes every run, the icon only works for that run.

How voice works:
- **Speech-to-text** runs on whisper on this Mac. Safari's built-in recognition works in a normal Safari tab but is
  unreliable in home-screen apps. Typing always works.
- **Replies** are spoken with iOS voices. For a nicer voice, download an "Enhanced" or "Premium" English voice under
  Settings › Accessibility › Spoken Content › Voices.
- Locking the phone or switching apps stops the mic. Tap once to resume.

## Quest 3

Pick one of these:

- **Over the tunnel:** open the **Viewer** link from `npm run up` in the Meta Quest Browser, then press Enter VR.
  Voice in the headset uses whisper, because the Quest Browser has no working speech recognition of its own.
- **Over USB** (works with `--local`, no internet needed):
  1. Turn on developer mode in the Meta Horizon app.
  2. Plug in USB-C and accept "Allow USB debugging" in the headset.
  3. Press `o` in the `npm run up` terminal. It runs `adb reverse` and opens `http://localhost:8787/?t=…` in the Quest
     Browser.
- **On the Mac:** open the Local link. With no headset attached, an emulated Quest 3 loads, so Enter VR works on the
  desktop too.

Move around by teleporting: push the thumbstick forward, or pinch and hold to aim. Grab things with the controller
triggers or a pinch.

## Talk to your world from the Claude app (claude.ai connector)

The app is also a remote MCP server at `https://<tunnel>/mcp/<token>`. Its tools are `look_around`, `summon`, `move`,
`remove`, `clear_world`, `set_mood` and `say`.

**Add the connector on claude.ai in a desktop browser:**
1. Go to **Customize › Connectors** (claude.ai/customize/connectors).
2. Choose **+ › Add custom connector**.
3. Enter a name (for example "Dreamspace"), then the **Claude** URL that `npm run up` printed.
4. For authentication, choose **No sign-in**. Then click **Add**.
5. In a chat, open **+ › Connectors** and switch Dreamspace on.
6. Set its tools to **Always allow**. Voice mode asks permission before each tool call, and it isn't known whether you
   can answer that by voice.

What's confirmed and what isn't (checked against Anthropic's docs, 2026-09-24):

| | |
|---|---|
| Custom connectors on Pro/Max, added on web or Desktop | Confirmed |
| Added on web, then usable in the iOS app | Confirmed |
| Adding a connector from the iOS app itself | Beta |
| iOS voice mode can use connected tools | Confirmed |
| …including a *custom* connector like this one | Implied, not stated |
| Answering a tool-permission prompt by voice | Unknown: use Always allow |
| No-sign-in (authless) servers, Streamable HTTP | Confirmed |
| A `trycloudflare.com` URL | Not named by Anthropic. It meets the stated rules (public HTTPS, IPv4, no redirect) |

Because the tunnel URL changes every run, edit the connector's URL each time (three-dot menu › Edit).

## Brains

Pick a brain on the phone or in the viewer. Brains fall back gracefully: if one fails, the next one answers.

| Brain | What it is | Speed |
|---|---|---|
| **claude** (default when available) | The `claude` CLI on your subscription, in one long-lived session. It can use only the world's MCP tools: no shell, no files, no web, no Gmail, and your CLAUDE.md is not loaded. `ANTHROPIC_API_KEY` is removed from its environment. | ~1–2 s per turn once warm |
| **ollama** | `qwen2.5:3b` on this Mac, returning JSON-schema replies with a guard that drops unsafe ops. Private and free. | ~0.7 s |
| **scripted** | Keyword rules. It runs the whole demo with no model at all. | Instant |

If Claude hits a usage limit, the local brain takes over for a while.

## Vibe mode (voice-code the world)

Turn on the **Vibe** toggle, then say what you want: "a slow ring of glowing lanterns", "make them orbit". Claude Code
writes a small three.js file in `creations/`, the server checks it, and it hot-loads into everyone's world.

Claude is confined to `creations/`. It can use Read, Write, Edit and Glob there, and nothing else: no shell, no web,
nothing outside the folder. A creation that breaks shows an error chip instead of breaking the scene. The rules it
follows are in `creations/README.md`.

## Meshy (later)

The `meshy` asset provider is written but stays off until `MESHY_API_KEY` is set in `.env.local`. Wait until Meshy
reaches out about the free Pro month; don't sign up before that. With a key, it turns text into a textured GLB, caches
it in `assets/meshy/`, and never pays twice for the same request. To choose the provider order, set
`ASSET_PROVIDERS=archetype,parts,meshy`.

## How it fits together

```
 iPhone Safari  /phone/  ─┐   SSE + POST (token)
 Quest / viewer  /       ─┼─►  server/app.mjs :8787 ──► brains: claude -p (MCP: world tools) │ ollama :11434 │ scripted
 claude.ai connector      │         │   │               assets: archetype │ parts (ollama) │ meshy (later)
   /mcp/<token>  ─────────┘         │   └─────────────► whisper-server :8178  (POST /api/stt)
                                    └─► vibe: claude -p in creations/ ──► /creations/<slug>.js hot-load
 cloudflared quick tunnel (https://….trycloudflare.com) ──► 127.0.0.1:8787
```

The server is one process on one port. `.data/` holds the world, logs and Claude's scratch folder. `models/` holds the
whisper model. Both are gitignored.

## Troubleshooting

- **"live updates can't get through this tunnel" (amber `polling` in the Tunnel row).** Replies travel over
  Server-Sent Events. Cloudflare's docs say quick tunnels don't support SSE, and some runs hold the stream back.
  `npm run up` opens the stream through the tunnel every run and wants its first bytes within 5 s. If they don't
  come, pages fall back to polling: replies still arrive, a few seconds late. For instant updates:
  - Try `TUNNEL_TRANSPORT_PROTOCOL=http2 npm run up`.
  - Or use a named tunnel or Tailscale.
- **"through the tunnel: /api/health failed (ENOTFOUND)".** A fresh trycloudflare name takes a few seconds to exist,
  and if this Mac asks too early, macOS remembers "no such host" for a minute. `npm run up` now waits for the name on
  public DNS (1.1.1.1) before it asks this Mac, and retries for 30 s. If it still shows, the phone and the Quest
  are usually fine (they use their own DNS); on this Mac, wait a minute or run
  `sudo dscacheutil -flushcache; sudo killall -HUP mDNSResponder`.
- **"port 8787 is busy".** Another `npm start` or `npm run up` is running. Stop it, or use `--port 8788`.
- **The first whisper start is slow (~40 s).** It compiles GPU shaders once. Later starts take about 2 s.
- **Enter VR is missing in the headset.** The page isn't on HTTPS or localhost. Use the tunnel Viewer link or USB.

## Lessons

- **Run one command, and check through the real path.** Testing health, SSE and MCP *through the tunnel* before
  printing the QR code catches failures in the terminal instead of in front of people.
- **Voice is whisper-first.** Safari's recognition is fine in a tab but flaky from the home screen, and the Quest has
  none. Local whisper works everywhere, and warm it takes ~0.2 s per clip.
- **Lock the headless Claude down properly.** `--allowedTools` only pre-approves tools; it restricts nothing.
  `--strict-mcp-config`, `--tools ""` and `--setting-sources ""` do the restricting. Never use `--bare`: it breaks the
  subscription login.
- **Keep a small local model on rails.** A JSON schema with enums built from the current world ids, plus a
  deterministic guard, took qwen2.5:3b from ~70% to 18 of 18 correct on held-out requests.
- **A quick tunnel is great for a demo but a poor home.** Its URL changes every run and it has one connection. A named
  tunnel is the upgrade when this becomes a daily tool.
